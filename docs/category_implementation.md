# Category Plan

Product categories for the A1Commerce store (e.g. "Men's Shirts", "Shoes").
Built on the i25Core foundation: `BaseEntity`, `BaseBusinessLayer<T>`, `BaseController<T>`.

## How to implement

Implement with the **`/create-i21core-entity`** skill (argument: `Category`), following its steps in order:

| Skill step | For Category |
|---|---|
| 1. Create Entity Model | `Core/Entities/Category.cs`, `Category : BaseEntity` |
| 2. Create Entity Mapping | `Core/Configuration/CategoryMap.cs` |
| 3. Register in DbContext | `DbSet<Category> Categories` + `ApplyConfiguration(new CategoryMap())` in `I25DbContext` |
| 4. Business layer interface | `ICategoryBusinessLayer : IBusinessLayer<Category>` |
| 5. Business layer | `CategoryBusinessLayer : BaseBusinessLayer<Category>, ICategoryBusinessLayer` |
| 6. Register in Program.cs | `AddScoped<ICategoryBusinessLayer, CategoryBusinessLayer>()` |
| 7. API controller | `CategoryController : BaseController<Category>` |

Where this plan differs from the skill's sample code:

- **No `INotifiable`** on `Category` (step 1): a category never receives notifications.
- **Non-generic business layer** (step 5): the skill sample `UserBusinessLayer<T> : BaseBusinessLayer<T> where T : BaseEntity, IUserBusinessLayer`
  does not compile as intended; use the concrete form above.
- **Steps the skill does not cover**, done after it: the validator, the access rules and the migration (sections below).

## Database structure

Table: `Categories`

| Column | Type | C# property | Rules | Description |
|---|---|---|---|---|
| Id | int | `id` (from `BaseEntity`) | Primary key, identity | Primary key |
| Name | nvarchar(128) | `string Name` | Required | Category name |
| Slug | nvarchar(160) | `string Slug` | Required, unique index | Unique URL-friendly name |
| Description | nvarchar(1000) | `string? Description` | Optional | Optional description |
| Image | nvarchar(512) | `string? Image` | Optional | Image path or URL |
| IsActive | bit | `bool IsActive` | Default `true` | Active status |

Added automatically by `BaseEntity` (every table in the app has them):

| Column | Type | Purpose |
|---|---|---|
| intConcurrencyId | int? | Concurrency token, incremented on every update |
| CreateAt | datetime2? | Set on insert |
| ModifiedAt | datetime2? | Set on insert and update |

Not included (add later only if needed): parent category / subcategories, sort order.

`Category` does **not** implement `INotifiable`: it never receives notifications (that is for `User`).

## Validation (`CategoryValidator`)

- `Name`: required, max 128.
- `Slug`: required, max 160, lowercase letters, digits and hyphens only (`^[a-z0-9]+(-[a-z0-9]+)*$`).
- `Description`: max 1000.
- `Image`: max 512.
- Slug uniqueness is enforced by the unique index; a duplicate becomes an error response through `GlobalExceptionHandler`.

## API endpoints

From `BaseController<T>`, available at `/api/Category` and `/api/v1/Category`:

| Method | Route | Action |
|---|---|---|
| GET | `/api/Category` | All categories |
| GET | `/api/Category/{id}` | One category |
| GET | `/api/Category/get` | Filtering, sorting, paging |
| POST | `/api/Category` | Create |
| PUT | `/api/Category` | Update |
| DELETE | `/api/Category` | Delete |

All responses use the standard `ApiResponse` envelope.

## Access

Default: **public read, Admin write.**

- GET endpoints are anonymous (the storefront lists categories without signing in).
- POST, PUT and DELETE require the `Admin` role.

Auth is on by default (`Auth:RequireAuthenticatedByDefault = true`) and `BaseController` actions carry no role
attributes, so this needs a small, reusable hook in `BaseController` that lets a controller mark its reads anonymous
and its writes admin-only. Alternative with no `BaseController` change: class-level `[Authorize(Roles = Roles.Admin)]`
(admin-only, storefront reads come later).

## Migration

1. Install the EF Core 8 tool as a local tool (the global 11.0 tool cannot load this net8.0 project):
   `dotnet new tool-manifest` + `dotnet tool install dotnet-ef --version 8.*`
2. `dotnet ef migrations add AddCategories --project A1Commerce.Infrastructure/A1Commerce.Infrastructure --startup-project A1Commerce.Web`
3. `dotnet ef database update` against the local `A1Commerce` database (also applies the four existing i25Core migrations).
